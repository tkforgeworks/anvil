# T-050 report: Save As and Backup through the save-location picker (ANVL-202)

## 1 Outcome
Done. File > Save As is enabled whenever a project is open and goes through `FileDialogs.pickSaveLocation`. The dashboard hero has an outlined `Backup` button next to Quick add that goes through the same picker. Both are covered by tests, and the full app suite is green.

## 2 Changes
- `lib/app/menu/menu_commands.dart`: `saveLocationPickerProvider` is now a non-null `Provider<SaveLocationPicker>`. It watches `fileDialogsProvider` and calls `pickSaveLocation` with `initialDirectory` set to the folder of `suggestedPath` and `suggestedName` set to its basename. The new public helper `splitFilePath(path)` splits at the last `/` or `\`, keeps a root such as `/` or `C:\`, and gives a null folder when the path has no separator (the app has no `package:path`). I removed the null checks in `commandEnabled` and `_saveAs`, and the `Needs a save dialog` tooltip.
- `lib/app/dashboard/backup_button.dart` (new):
  - `defaultBackupName(projectName, now)` reproduces 0.1.6's `backupProject` name exactly: `<name with [^a-zA-Z0-9_-]→_>-backup-<UTC YYYY-MM-DD>.anvil`.
  - `backupFolderOf(metadata)` gives `projectFolder.root`, or the file's folder when the project has no folder structure.
  - `backupSavedMessage(path)` gives `Backup saved to <path>`.
  - `BackupButton(project:)` (key `dash-backup`, `Icons.download`, `onPrimary` foreground with a 0.5-alpha border) reads the clock from `clockProvider`. A cancel does nothing. Otherwise it calls `ProjectLifecycleNotifier.backup` and shows either the success snackbar or the lifecycle's failure message.
  - The button is disabled while the lifecycle is `LifecycleBusy`. After the dialog it returns quietly if the lifecycle is busy or no session is open, because `backup()` returns null in both cases without writing anything, and the snackbar would otherwise report a backup that never happened.
- `lib/app/dashboard/dashboard_page.dart`: the hero shows Backup and Quick add. Below `_Hero.buttonsBesideWidth = 640` the hero's content sits in a `LayoutBuilder` that puts the two buttons on their own right-aligned row under the project details.
- `test/menu/app_menu_test.dart`:
  - The tooltip test now asserts Save As is enabled.
  - New `splitFilePath` unit test.
  - New `Save As through the save dialog` group over `FakeFileDialogs`:
    - cancel: the request goes out as `save location from <folder> as sample.anvil`, the session is the same object, nothing is written, no snackbar;
    - success: the session switches to `<tmp>/copy.anvil`;
    - failure (target exists): `A project file already exists at that path.` is shown and the session is kept.
  - The old override-based Save As test is replaced by the success case.
- `test/dashboard/backup_button_test.dart` (new, 6 tests): the pure name and folder rules, then the button over `PageHarness` with a real fixture session and `FakeProjectService`:
  - cancel: the request is `save location from /projects/Spike Fixture as Spike_Fixture-backup-2026-11-01.anvil`, no snackbar, session unchanged;
  - success: the file is written with no lock sidecar, the snackbar shows, and the session is the same object, still open, with the same path;
  - failure (target = the open file): `A backup cannot replace the open project file.`, session kept;
  - no session: nothing is claimed.

## 4 Deviations
- **Backup start folder.** I followed the brief: the project's folder root. 0.1.6 and the core's `defaultBackupPath` both start in the folder holding the `.anvil` file (`database/`). I kept the brief's decision and noted the difference in `backupFolderOf`'s doc comment.
- **Backup file name.** 0.1.6's exact name (`-backup-<YYYY-MM-DD>`, UTC date) instead of the brief's suggested `_backup_<yyyyMMdd-HHmmss>`, as the brief asked when an oracle name exists. The alternative I rejected was reusing `ProjectService.defaultBackupPath`, because it reads the core's clock, not `clockProvider`.
- **Picker provider type.** `saveLocationPickerProvider` is now non-nullable, and the dead disabled tooltip is gone. The alternative I rejected was keeping it nullable with a non-null default.
- **Hero layout.** The hero now stacks its buttons below 640 px. The existing 500 px "tiles wrap" test overflowed by 43 px with the second button. The alternative I rejected was icon-only buttons.
- **Success message.** It shows the path exactly as the dialog returned it. The core writes `path.trim()` and does not add `.anvil`, as 0.1.6 did.
