# T-062 report: core data layer (`cdl`) at `a0823e2`

All paths below are under `packages/anvil_core/lib/src/` unless they start with `lib/`, `test/` or `packages/`.

## 1. Summary

The data layer works and is well documented. The boundaries hold: no `sqlite3` type or SQL crosses a repository interface, and no repository writes outside `ProjectDatabase.saveTransaction`. Most files are within the thresholds. The structural debt is copying more than size. These are the top three problems:

1. **The six `Sqlite*` domain repositories each repeat the same ~60–80 lines.** This covers the `_Select` typedef, `_where`, `list`, `countActive`, the get/require helper, `_checkExportKey`, the throw-on-blockers block, and soft-delete/restore/hard-delete. Item and NPC also copy the custom-field-value SQL from each other. The NPC repository copies class stat-growth reads from the class repository and the stats query from the meta repository.
2. **`MetaRepository` is a 38-method fat interface.** 20 of its methods (the immediate CRUD for stats, rarities, stations, specialisations and derived stats) have no caller in `lib/`, and six test fakes implement it through `noSuchMethod`. `SqliteMetaRepository` (761 lines) also mixes four jobs: table descriptors, list CRUD, the 0.1.6 in-use rules, and the buffered settings commit.
3. **Layering and placement drift.**
   - `repositories/` and `project/` import each other (`RecordCounts` lives in `project_metadata.dart`).
   - `repositories/` imports `export/js_compat.dart`, and `domain/` imports `db/`.
   - Result types such as `MetaInUseResult`, `AbilityUsedBy`, `ItemUsedBy` and `UpdateCustomFieldDefinitionInput` sit in repository interface files.
   - `project_service.dart` (745 lines, 5 public types) holds isolate pre-open checks, a metadata reader and path helpers beside the service.
   - The barrel exports internals the app never uses.

## 6. Discrepancies

- **CLAUDE.md, "every domain repository has the same shape … `usedBy`".** `RecipeRepository` and `NpcRepository` have no `usedBy` (`repositories/recipe_repository.dart:17-53`, `npc_repository.dart:24-74`). `usedBy` also returns three different shapes: `AbilityUsedBy`, `ItemUsedBy` and `List<UsedByRef>`.
- **CLAUDE.md, "the raw handle is an `@internal` getter for the core's own repositories".** No repository uses `handle`; its users are the migration runner and `ProjectService` (`project_service.dart:148,150,555,650`).
- **CLAUDE.md, "a `SqliteException` never escapes a public method".** True of `saveTransaction`, the repositories and `ProjectService`. `ProjectDatabase.open`/`openReadOnly`/`snapshot`/`checkpoint`/`read` document that they may propagate it (`db/project_database.dart:16-19`), and they are public via the barrel.
- **Brief, "`settings/app_settings.dart`: four functions over cc 10".** Two are in `app_settings.dart` (`normalize` 12, `copyWith` 13); the other two are in `settings/custom_theme_colors.dart` (`operator []` 12, `parseCustomThemeSource` 11).
- **Brief, "`repositories/**` (25 files, ~4,170 lines)".** 25 files, 4,140 lines.
- **Metrics, `dup_private.csv` shows nothing in this area.** It counts classes only. The duplicated private functions and typedefs (`_Select` ×8, `_where` ×6, `_checkExportKey` ×6, `_get`/`_requireRecord` ×6, `_insertValue` ×2, `_isoNow` ×2) are invisible to it.
- **Metrics, `files.csv`, `domain/equality.dart` public types 0.** Correct for classes, but it has 9 public `@internal` functions plus the `unset` constant. Its header says it is not in the barrel (true: `domain/domain.dart` omits it).
