## Expected outcome
- Public API mirroring Electron: `FormulaEvalResult evaluateFormula(String formula,
  Map<String, double> bindings)` with `value` (double?), `error` (String?), `isSyntaxError`;
  `String? validateFormula(String)`; `List<String> extractVariableNames(String)` (same ordering
  and de-duplication as Electron); `FormulaSyntaxError`/`FormulaRuntimeError` as exceptions with
  the messages verbatim (`Unexpected character 'x' at position 3`, `Expected RPAREN but found ''
  at position 5`, `Unexpected end of formula`, `Unknown variable 'x'`, `Division by zero`,
  `Unknown function 'x'`, `Formula is empty`, and every other message string in `engine.ts`;
  grep them all).
- JavaScript number semantics reproduced: lexer consumes `[0-9.]+` and takes the longest valid
  `parseFloat` prefix (`1.2.3` → 1.2, `.5` → 0.5, `5.` → 5, `.` → NaN or whatever Electron does;
  the corpus decides); `min()`/`max()` with no args → ±Infinity; `floor()`/`ceil()` with no args →
  NaN; division fails only on exact zero (so `1/0.0` is an error, `1/-0.0`: check); results that
  are NaN/Infinity are reported however Electron reports them (value vs error; the corpus
  decides). Variable names: same identifier charset as Electron's lexer.
- Parity corpus: at least 120 cases covering every error message, each number edge case above,
  nested calls, unary minus (including `--3`, `-(2)`, `2*-3`), parenthesised precedence,
  whitespace variants, unknown identifiers, missing/extra parens and commas, empty and
  whitespace-only formulas, and realistic Anvil formulas (`floor(base_hp + level * hp_growth)`,
  `max(1, strength * 0.5)`); each case `{formula, bindings, value, error, isSyntaxError}` with
  JSON-safe encoding of NaN/±Infinity (strings `"NaN"`, `"Infinity"`, `"-Infinity"`, documented).
  `parity_test.dart` runs every case and asserts value (exact double equality, NaN == NaN by
  `isNaN`), error string and syntax flag.
- Caches: `FormulaEngine` class holding a parse cache (formula text → AST) and an evaluation
  cache keyed by (formula, bindings) with value equality on the bindings map; top-level functions
  stay stateless convenience wrappers. Tests prove a second evaluation hits the cache (count
  parses with a visible counter or a `@visibleForTesting` hook).
- `Future<List<FormulaEvalResult>> evaluateBatch(String formula, List<Map<String, double>>
  bindingsList)`: parses once, evaluates in-isolate below `isolateThreshold` and via
  `Isolate.run` at or above it. Write `benchmark/formula_benchmark.dart` that times N
  evaluations in-isolate vs `Isolate.run` for N in {500, 1000, 2000, 5000, 10000} (release-mode
  `fvm dart run`, 5 repetitions, median) and set `isolateThreshold` to the measured crossover
  rounded to a round number; design default is 2000. Record the numbers in your report and in a
  doc comment on the constant.
- `derived_stat_cycles.dart`: given derived stat definitions (id, display name, formula) and an
  optional per-class override map (derived stat id → formula), build the dependency graph by
  `extractVariableNames` matching other derived stats' export keys (check how Electron matches:
  by export key or id), and return the cycle as the list of names in Electron's order plus the
  exact message `Derived stat is part of a dependency cycle: ${names.join(' → ')} → ${names[0]}.`
  Tests: no cycle, self-cycle, 3-node cycle, a cycle introduced only by a class override, and a
  cycle broken by an override.
