## Decisions already taken (do not re-decide)
- Drafts carry no id, so the save signature is `Future<ClassDraft> save(String id, ClassDraft
  draft)`; `create` and `duplicate` return the `XRecord` (the caller needs the new id).
- `load(id)` returns the draft for any existing row, soft-deleted or not (the recycle bin may
  show it); `save` requires `deleted_at IS NULL` and throws `RecordNotFound` otherwise.
- `softDelete`, `restore`, `hardDelete`, `duplicate` throw `RecordNotFound` for an unknown id
  (0.1.6 silently did nothing); each is its own `saveTransaction` with its own history row.
- The export-key uniqueness check runs in Dart before the write (`SELECT 1 FROM <table> WHERE
  export_key = ? AND id != ?`) and throws `DuplicateExportKey(key)` with the key filled in, so
  the `UNIQUE` constraint is never reached in the normal path.
- Save blockers are pure functions in the domain layer, exported from `domain.dart`:
  `List<SaveBlocker> classSaveBlockers(ClassDraft draft)` in
  `lib/src/domain/class_save_blockers.dart` and `List<SaveBlocker> abilitySaveBlockers(AbilityDraft
  draft)` in `ability_save_blockers.dart`. The repository `save` calls the same function and throws
  `SaveBlocked([for (final b in blockers) b.message])` when it is non-empty, before any write.
  Rules (design §8.6, confirm the messages and any extra rule against the editors): empty display
  name or export key (after trim); duplicate ability ids in `abilityIds`; a stat growth level
  below 1; a derived stat override whose formula fails `validateFormula` (field
  `derivedStatOverrides.<derivedStatId>`); a metadata field key not matching
  `^[a-zA-Z_][a-zA-Z0-9_]*$` or duplicated (field `metadataFields[<i>].fieldKey`). Broken
  references (an ability id that no longer exists) are NOT blockers; they surface as a validation
  issue, and a foreign-key failure in SQLite would arrive as `SaveFailed`.
- Resolved stat growth (0.1.6 `getStatGrowthWithFormulas`) is a pure function
  `Map<StatGrowthKey, double> resolveStatGrowth({required Map<StatGrowthKey, double> manual,
  required Map<String, String> formulas, required int maxLevel})` in
  `lib/src/domain/stat_growth.dart` (exported from `domain.dart`): manual entries for a stat that
  has a formula are dropped; each formula is evaluated for levels 1..maxLevel with bindings
  `{level, max_level}` and `value ?? 0` on error, exactly as the Electron method. The repository
  adds `Future<Map<StatGrowthKey, double>> resolvedStatGrowth(String id)` that reads `max_level`
  from `project_info` and the draft's growth inside one `read` and calls the function.
- Duplicate uses `copyDisplayName` / `copyExportKey` and copies every junction list, as
  `class.repository.ts` did.
- Do not touch `lib/src/project/project_session.dart`: wiring the repositories into the session
  is ANVL-179.
