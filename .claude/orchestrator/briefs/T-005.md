## Goal
Implement Jira FU-12. `forgeTheme` sets no `ScrollbarThemeData`, so desktop apps get the platform default thumb, which ignores the palette and is often invisible on dark surfaces.

## Design (decided; implement this)
- In `forgeTheme`, set `scrollbarTheme: ScrollbarThemeData(...)` for BOTH densities with: `thumbColor: WidgetStatePropertyAll(x.textGhost)` (a token, so it follows the palette; use `x.textTertiary` when hovered/dragged via `WidgetStateProperty.resolveWith`), `thickness: WidgetStatePropertyAll(8)`, `radius: Radius.circular(ForgeRadii.tag)`, `crossAxisMargin: 2`, `mainAxisMargin: 4`. Set `thumbVisibility: WidgetStatePropertyAll(true)` ONLY when `density == ForgeDensity.desktop`; leave it null for touch (Material's default: fade out). `trackVisibility` stays null.
- Touch goldens must not change: a `ScrollbarThemeData` with no visible scrollbar in the gallery (no scroll happening in the golden) should be pixel-identical; verify by running the existing goldens BEFORE `--update-goldens`. If a touch golden changes, make the whole `scrollbarTheme` desktop-only and say so.

## Tests (`test/theme_test.dart`)
- Thumb colour equals `x.textGhost` (default state) for both densities; thickness 8; radius `ForgeRadii.tag`.
- `thumbVisibility` resolves true for desktop and is null for touch.
- A `testWidgets` with a `ListView` of 100 items inside `MaterialApp(theme: forgeTheme(seed: testSeed, density: ForgeDensity.desktop))` on a 400×300 surface: `find.byType(Scrollbar)` or `RawScrollbar` is found (Material adds one on desktop platforms; run under `TargetPlatformVariant.desktop()`), no exceptions.
