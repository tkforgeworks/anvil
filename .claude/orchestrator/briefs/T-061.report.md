# T-061 report: shell, project lifecycle and pages (area `shp`)

Baseline: `a0823e2` on `review/1.0.0-baseline`. Read-only review; `fvm flutter analyze` → `No issues found!`; `git status --porcelain` → `?? node_modules/` only.

## 1. Summary

The area is in good shape. Files are small (largest 391 lines), well commented and analyzer-clean, and the provider rules hold: no widget watches `requireSessionProvider` or a repository provider, and `go_router` is confined to `lib/app/shell/`. The debt is structural, not local. The top three problems:

1. **Adding a domain is spread across files.** Inside this area, a seventh domain means editing ~12 sites in 7 files: three registry maps, three validation switches, a 6-arm repository `switch`, a quick-add map, and count aggregations. Outside it there are ~6 more. The registry maps are looked up with `!`, so a missing entry fails at runtime, not at compile time.
2. **Dead scaffolding and hidden globals left over from the rewrite.** `PagePlaceholder` / `EditorPlaceholder` / `_domainTickets` can no longer be reached. The `editorBuilders` map is a mutable top-level global that a test reassigns. Quick add still has an "unavailable" branch, and a few unused public constants remain.
3. **Mixed-responsibility provider files and long `build()`s.** `shell_providers.dart` holds the session guard, 11 repositories, the write epoch, counts, the validation notifier and the sidebar state. `providers.dart` has an import cycle with `settings/app_settings_notifier.dart`. Five `build()` methods are over 100 lines or have cc > 15 (validation page, recycle bin page, create dialog, recent row, sidebar).

## 6. Discrepancies

- **The brief's `_Hero` ×2 and `_Footer` are not duplicates.** They only share names. Welcome `_Hero` (`welcome_page.dart:95-127`) is a heading; dashboard `_Hero` (`dashboard_page.dart:133-258`) is the project banner. Welcome `_Footer` (`welcome_page.dart:286-333`) is the local-first note plus the settings button; Project Settings `_Footer` (`settings/project/project_settings_dialog.dart:190`) is the save bar. Nothing to extract. `_Panel` recycle bin ≡ export is a real duplicate (F16); the class tab's `_Panel` is not.
- **Line counts are offset by one.** `files.csv` line counts are `wc -l` + 1 (`project_lifecycle.dart` 392 vs 391, `sidebar.dart` 359 vs 358, `recycle_bin_controller.dart` 354 vs 353). `functions.csv` lines point at the `@override` line, one above the signature (e.g. `create_project_dialog.dart:119` → `build` at `:120`). The brief's figures match `wc`.
- **`providers.dart` contradicts its own doc.** It says "Feature providers live beside the feature they serve, not here" (`:4-5`) but holds `appSettingsProvider` and the session and service providers. `:51-52` says the welcome page sets and clears the session; only `ProjectLifecycleNotifier` does.
- **CLAUDE.md: "`placeholders.dart` is the page registry each domain registers into".** Domains do not register. `placeholders.dart` imports each `*_pages.dart` and lists their builders (`:12-17`, `:51-69`), and its placeholder entries are dead.
- **CLAUDE.md lists `AnvilLayout` as a non-colour constant set.** It still carries the dropped title bar's `titleBarHeight` (`anvil_metrics.dart:34`) with no users.
- **`last_checked.dart:16` is literally right but depends on the dashboard.** It says the dashboard keeps the provider alive; that only holds while sessions open on `/` (F23).
