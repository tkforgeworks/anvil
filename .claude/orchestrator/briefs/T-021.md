## Decisions already taken (do not re-decide)
- `NpcRepository` has exactly the common shape of the five existing domain repositories (same
  method names, signatures, error behaviour, history descriptions, `save(id, draft)`, duplicate
  via `copyDisplayName`/`copyExportKey`, `RecordNotFound` on unknown ids). No `usedBy` (nothing
  references NPCs). `combat_stats_json` round-trips through `jsonEncode`/`jsonDecode` with the
  stored key order kept. Custom field values are handled as `sqlite_item_repository.dart` does for
  items, scoped to the NPC type. Blockers in `lib/src/domain/npc_save_blockers.dart`
  (`npcSaveBlockers(NpcDraft)`): empty display name / export key, empty `npcTypeId`, a class
  assignment level below 1, duplicate class ids, duplicate ability ids, plus whatever the editor
  disabled Save on.
- `Future<Map<String, double>> inheritedStatBlock(String id)` on `NpcRepository` reads the NPC's
  class assignments and each class's resolved growth (through the same SQL
  `SqliteClassRepository.resolvedStatGrowth` uses, inside one `read`) and returns
  `computeNpcStatBlock(...)`; use the C4 function, do not re-implement the sum.
- `LifecycleDomain` enum in `lib/src/domain/lifecycle_types.dart` with the six 0.1.6 strings
  (`classes`, `abilities`, `items`, `recipes`, `npcs`, `loot-tables`) and a mapping to table name
  and `SaveDomain`; `DeleteImpact` result type mirroring `impact.ts`'s shape; `DeletedCounts` or
  reuse `RecordCounts` for `countDeleted()` (prefer `RecordCounts`, it already has the six keys).
- `LifecycleRepository` in `lib/src/repositories/lifecycle_repository.dart` with
  `SqliteLifecycleRepository`: `countDeleted()` → `RecordCounts`, `bulkSoftDelete(domain, ids)`,
  `bulkRestore(domain, ids)`, `bulkHardDelete(domain, ids)` (each ONE `saveTransaction` with
  `bulkChanged(saveDomain, ids.length, action)`; the same SQL per row as the domain repository;
  ids that do not exist are skipped silently as 0.1.6 did, but the count in the description is the
  number of rows actually changed), `emptyTrash()` (one transaction hard-deleting every
  soft-deleted row across the six tables in 0.1.6's table order; description: what 0.1.6
  recorded, check `lifecycle.handlers.ts`), `computeDeleteImpact(domain, ids)` (pure read, port of
  `impact.ts` returning the same summary for the fixture), `weeklyDeltas()` → `RecordCounts`.
- `SaveHistoryRepository` in `lib/src/repositories/save_history_repository.dart`: `recent({int
  limit = saveHistoryLimit})` → `List<SaveHistoryEntry>` newest first, implemented by
  `SqliteSaveHistoryRepository` over the existing `readRecentSaves`. Rows are written only by
  `saveTransaction`.
- `ProjectSession` gains `final` fields `classes`, `abilities`, `items`, `recipes`, `npcs`,
  `lootTables`, `meta`, `customFields`, `templates`, `saveHistory`, `lifecycle`, each typed as the
  interface and built from the session's `database` in the constructor (`ProjectSession.open(
  metadata, database, lock)` factory or constructor body: keep the `@internal` constructor and the
  four `ProjectService` call sites compiling with the smallest change). `TemplateRepository` /
  `SqliteTemplateRepository` (ANVL-182) are merged on `v0.2.0/main` and in your worktree's base.
- Barrels: `lib/src/repositories/repositories.dart` and `lib/src/domain/domain.dart` get one
  `export` line per new public file, lists kept sorted. `lib/anvil_core.dart` is untouched.
