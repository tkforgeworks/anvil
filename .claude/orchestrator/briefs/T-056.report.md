## 2 Changes
- `scripts/install/install-anvil.sh` (630 lines). It starts with the header and help.
  - **Method:** deb when `dpkg-query -W dpkg` reports "install ok installed" and apt-get exists; rpm when `rpm -q rpm` succeeds and dnf exists; otherwise the AppImage. `--appimage` forces the AppImage.
  - **JSON:** read with `python3 -I -c`, which picks the release and the exact asset name `anvil-<ver>-<suffix>`.
  - **Version compare:** `dpkg --compare-versions` on deb, `rpm --eval '%{lua: print(rpm.vercmp(...))}'` on rpm (falling back to `rpmdev-vercmp`), and a pure X.Y.Z[-rc.N] compare for the AppImage.
  - **sudo:** `sudo -v`, then a keep-alive loop guarded by `kill -0 $$`, killed in the EXIT trap; deb and rpm paths only, and only when an install will happen.
  - **Install commands:** `apt-get install -y [--allow-downgrades] <abs path>`; `dnf install -y` or `dnf downgrade -y` with a local file (both work on dnf5).
  - **Temp files:** a `mktemp -d` dir removed by the trap.
  - **Pipe safety:** everything runs inside `main "$@"`, and children get `</dev/null`, so `curl | bash` is safe.
  - **AppImage:** extracts `com.tkforgeworks.anvil.{desktop,png}` with `--appimage-extract <name>`. It installs `~/.local/bin/anvil` by rename, so a running copy keeps its old file, and writes the desktop file with `Exec=<abs path> %U` (quoted and escaped per the Desktop Entry spec when the path needs it) and `Icon=com.tkforgeworks.anvil`. The icon goes in `hicolor/512x512/apps`, the tag in `~/.local/share/anvil/installed-version`. It runs `update-desktop-database` if present and warns when `/usr/bin/anvil` exists, when `~/.local/bin` is not on PATH, and when `fusermount` is missing.
  - **Final check:** after installing, it re-reads the installed version and fails if it is not the target.
- `scripts/install/install-anvil.ps1` (451 lines).
  - **Pure functions:** `ConvertTo-AnvilVersion`, `Compare-AnvilVersion`, `Get-JsonProperty` (safe under StrictMode), `Select-AnvilRelease`, `Get-AnvilAssetName`, `Find-AnvilAsset`, `Get-ExpectedSha256`, `Get-InstallerArgumentString`, `Get-SetupExitMeaning`.
  - **Host functions:** `Get-UninstallEntry` (HKCU, then HKLM in both the 64-bit and WOW6432Node views), `Test-Elevated`, `Invoke-AnvilApi` (null on 404), and the main body `Invoke-AnvilInstall`.
  - **Main guard:** `if ($MyInvocation.InvocationName -ne '.')`.
  - **Setup command line:** `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /CLOSEAPPLICATIONS /NORESTARTAPPLICATIONS`, plus `/ALLUSERS` or `/CURRENTUSER`, `[/DIR="…"]` and `/LOG="%TEMP%\anvil-setup-<ver>.log"` (the log is kept only on failure). It runs through `Start-Process -Wait -PassThru`, and a non-zero `ExitCode` throws with what the code means.
  - **5.1 handling:** TLS 1.2 is added on Desktop edition, and `$ProgressPreference` is silenced during `Invoke-WebRequest -UseBasicParsing`.
  - **Checks and reporting:** the download is checked with `Get-FileHash`; a 0.1.x Electron install is reported as "Older"; a running `anvil` process gets a warning.
- `scripts/install/test/make-fake-release.py`: writes `api/releases/index.html` (the list, served for `/releases?per_page=100` through http.server's directory redirect), `api/releases/latest`, `api/releases/tags/<tag>`, `api-old/` (newest = rc.1, for the no-downgrade case) and `download/<tag>/<name>`. Releases:

  - `v0.2.0`: stable.
  - `v0.2.0-rc.1`: prerelease; its AppImage digest is null, to exercise the missing-digest warning.
  - `v0.1.6`: the real electron-builder names and digests.
  - `v0.0.9`: every digest deliberately wrong.
- `scripts/install/test/linux-scenarios.sh`: the in-container scenarios. Every run pipes the script into `bash -s --` as a non-root `tester` with passwordless sudo, and the script prints PASS/FAIL per check.
- `scripts/install/test/run-container-tests.sh`: podman runner with jobs `fedora`, `debian`, `ubuntu`, `appimage`, `lint` (shellcheck) and `pwsh`.
- `scripts/install/test/test-install-anvil.ps1`: a test script with no Pester dependency.
- `README.md`: a new `## Install` section before the Flutter section, with the one-liners, the options, the "serves from main" note with the checkout fallback, a manual-install table, and a link to the upgrade note. Nothing else in the README changed.

## 4 Deviations
- **The deb `Version` is `0.2.0-1` / `0.2.0~rc.1-1`, not `X.Y.Z~rc.N`.** nfpm appends `release: "1"` as the Debian revision. dpkg ranks `0.2.0-1` above `0.2.0`, so the script compares the upstream part with the revision stripped; 0.1.6's deb has none. The rpm keeps `VERSION` and `RELEASE` separate, as the brief said.
- **`--check` / `-Check` exit 1 when the release has no host asset**, after printing the Release and Installed lines, instead of exiting 0. The rejected alternative was exit 0 with nothing installable. For now this means `--check` against real GitHub fails for every tag until a 0.2.0 release is published (newest and latest are both v0.1.6).
- **Windows passes `/NORESTARTAPPLICATIONS` and `/NORESTART`.** `/VERYSILENT` reboots without asking unless `/NORESTART` is given. `Start-Process -Wait` waits for descendants, so an Anvil restarted by Restart Manager would hang the script. The help says Anvil is asked to close, never force-closed, not reopened, and that Setup fails if it stays open. The rejected alternatives were Inno's default restart and `/FORCECLOSEAPPLICATIONS`, which would lose unsaved edits.
- **Windows scope:** an existing all-users 0.2 install is updated with `/ALLUSERS` (elevation required) instead of `/CURRENTUSER`, which would create a second per-user copy. Without elevation, an all-users install throws "needs an elevated PowerShell" rather than relying on Setup's own UAC prompt.
- **A failure ends the PowerShell script with `exit 1` only when it runs as a file.** As a script block, `exit` would close the user's window, so the script sets `$LASTEXITCODE` instead. `$PSCommandPath` could not be used for this test: a script block sees its caller's value.
- **The AppImage paths use `$XDG_DATA_HOME`** (default `~/.local/share`), not a hard-coded `~/.local/share`.
- **The deb path runs `apt-get update` (non-fatal) before installing**, so the dependencies resolve on hosts with stale lists. Container lists start empty.
- **The rc.1 test packages were repackaged from the 0.2.0 bundle** with `--skip-flutter-build`, not built with Flutter, so the binary's `version.json` still says 0.2.0. This does not affect the package tests.
- **The pwsh job uses the `7.5-ubuntu-24.04` image tag.** `powershell:latest` is a two-year-old 7.4.2, and PSScriptAnalyzer refuses to load below 7.4.6.
- **The shellcheck job is named `lint`.** A help line starting `#   shellcheck` parses as a shellcheck directive (SC1073).
- **The default release is the first non-draft in the API list** (GitHub's newest-first order by creation date), not the highest version.

## 5 Open questions

- Should the deb path run `apt-get update` on every run? It costs a few seconds and protects against stale package lists.
