# T-063 report: 1.0.0 baseline review, core engines (`eng`)

Scope: `packages/anvil_core/lib/src/{formula,export,validation}/**` at `a0823e2`. Paths below are relative to
`packages/anvil_core/lib/src/` unless they start with `lib/`, `test/` or `packages/`.

## 1. Summary

The three engines are in good shape. Each file has its 0.1.6 source documented, and the parity corpora pin the
behaviour. Most of the hot-spot complexity is ported JavaScript or Nunjucks algorithms, which should be exempt
rather than split. The real structural problems:

1. **`validation/validate_project.dart` (752 lines)** holds all seven check families plus their shared SQL
   helpers. It is over the 500-line hard limit, and `_checkDerivedStatCycles` is cc 16, above the hard limit of 15.
2. **The export presets are not open/closed.** A new preset means editing `presets.dart`, the `builtInPresets` list
   and the string `switch` in `export_service.dart`, and `export.dart`. The same file also keeps the pipeline logic
   inside the `Isolate.run` closures. The template filters have the same problem: the names are listed twice
   (`filters` map and `supportedFilters`).
3. **Dependency tangles.** `formula_engine.dart` and `formula_batch.dart` import each other. The repositories
   import `export/js_compat.dart` for `jsonStringify`. The six-domain list is copied three times inside `export/`,
   and as four enums across the core (cross-area).
