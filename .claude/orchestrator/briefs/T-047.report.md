## 5. Deviations
- I checked every brief name against the source; all match. Migration 002 does seed crafting specializations (4 of them), and its ids are `<table-prefix>-<slug>`. The `affinities` table exists but nothing seeds it; templates leave it alone.
- I did not add new template row types. `ProjectTemplateContent` reuses the domain `Meta*` and `DerivedStatDefinition` types, which already carry id, display name, export key and sort order. The rejected alternative was separate template row records that would duplicate them.
- `validateFormula(formula)` checks syntax only and takes no stats. To check formulas "against that template's own stats", the content test also asserts that `extractVariableNames` is a subset of the template's stat keys. The create test then runs `validateProject` with one class added, because with no classes the engine evaluates no formula: I confirmed this with a throwaway probe, which showed no issues without a class and a `Division by zero` issue with one.
- The failure seam is an overridable `@visibleForTesting @protected` method (`templateContentFor`), not a constructor parameter. `FakeProjectService` keeps its constructor unchanged. The rejected alternative was a function-typed constructor argument.
- "Not marked dirty": the 0.2.0 app has no project dirty flag, since save status comes from editor drafts. The tests assert zero `save_history` rows in both core and app instead.
