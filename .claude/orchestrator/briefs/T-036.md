## Goal
Give the shared list scaffold's instant actions (soft delete, restore, duplicate, bulk soft delete,
bulk restore) a short-lived Undo snackbar whose Undo applies the inverse action through the same
controller paths, so every action and every undo is one repository write with one history row and
one write-epoch bump. Hard delete, bulk hard delete (and later Empty Trash) keep their confirms and
get no Undo. Create dialogs are untouched. Jira ANVL-166 (the orchestrator handles Jira).

## Decisions already taken (do not reopen)
- New file `lib/app/lists/undo_snackbar.dart`: `showUndoSnackBar(BuildContext, {required String message,
  required Future<void> Function() undo, Duration duration = undoSnackBarDuration})` with
  `undoSnackBarDuration = Duration(seconds: 5)`; it hides the current snackbar first so only the
  latest action is undoable (the earlier one stays applied), shows `message` with an `Undo`
  `SnackBarAction` (key `ValueKey('undo-snackbar-action')`, the snackbar itself `ValueKey('undo-snackbar')`),
  and does nothing when there is no `ScaffoldMessenger` (`maybeOf`). The ANVL-199 recycle bin reuses
  it, so it must not depend on `RecordListController`.
- Messages, with the display name in quotes and the domain words from `ShellDomain`:
  `Deleted "<name>"`, `Restored "<name>"`, `Duplicated "<name>" as "<copy name>"`,
  `Deleted <N> <label lower-cased>` and `Restored <N> <label lower-cased>` for bulk (`Deleted 3 abilities`;
  `1` uses the singular lower-cased: `Deleted 1 ability`).
- Inverses, all through the controller so the busy flag, error line and epoch bump apply:
  soft delete ↔ `restore(id)`; restore ↔ `softDelete(id)`; bulk soft delete ↔ `bulkRestore` of the
  SAME ids (not the current selection: add controller methods `restoreIds(List<String>)` /
  `softDeleteIds(List<String>)` that run `_runBulk`'s write over given ids, or refactor `_runBulk`
  to take the ids); bulk restore ↔ bulk soft delete of the same ids; duplicate ↔ `hardDelete(copyId)`
  (the copy is new, so a hard delete is the exact inverse and writes its own history row). Before
  the duplicate Undo hard-deletes, if `dirtyEditorsProvider` holds an entry for the copy, call its
  `discard` so no stale dirty editor survives; after it, if the current location is the copy's editor
  route (`ShellDomain.editorLocation(copyId)`), go to the domain's list through
  `ref.read(routerProvider)`; in modal mode the dialog sits above the snackbar, so Undo is reachable
  only after the dialog closes, which is accepted.
- The controller gains nothing UI-specific: the page (`RecordListPage`) shows the snackbar after
  each successful action (the controller's future completes with `lastError == null`); on failure
  no snackbar, the error line already reports it. Expose what the page needs (e.g. `softDelete`
  returning `bool` success, or reading `lastError` after the await) with the smallest change.
- Hard delete, bulk hard delete: unchanged (confirm dialogs, no snackbar). Create dialogs: unchanged.
- An Undo that fails sets `lastError` as any action does; the snackbar is gone by then.
- Remove the two "ANVL-166 replaces this" comments once replaced.
