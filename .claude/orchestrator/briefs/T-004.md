## Goal
Implement Jira FU-9. `ForgeTokens` carries only `successContainer`/`onSuccessContainer`. Add full warning, info and success roles so apps read `context.forge.warning` etc. instead of declaring their own.

## Design (decided; implement this)
- New fields on `ForgeTokens`: `warning`, `onWarning`, `warningContainer`, `onWarningContainer`, `info`, `onInfo`, `infoContainer`, `onInfoContainer`, `success`, `onSuccess`. The existing `successContainer`/`onSuccessContainer` stay as they are.
- The ten new fields are OPTIONAL in the `const` constructor with defaults, so Cheesy Scribe's and Anvil's existing `ForgeTokens(...)` literals (see `test/support.dart` `DesignedPalette.lightTokens`, which must compile unchanged) keep working. Since a `const` constructor cannot derive defaults from other fields, make them nullable-backed: store `Color? _warning` etc. and expose non-nullable getters that fall back to the light-brightness fixed hue? No: a `ThemeExtension` with brightness-unaware fallbacks would be wrong in dark mode. Do this instead: constructor parameters `Color? warning, ...` (optional), stored as nullable private fields, and public getters `Color get warning => _warning ?? _defaultWarning(_isDarkHint)` where the brightness hint is inferred from `successContainer`'s luminance (dark container → dark defaults). Document this fallback in the doc comment. `ForgeTokens.standard(scheme)` passes all ten explicitly from the scheme's brightness, so the fallback only matters for hand-written literals that predate FU-9.
- Fixed hues (the MUI defaults Anvil's Electron themes used; chosen so Anvil's theme tests keep passing when it adopts them):
  - dark: warning `#FFA726`, info `#29B6F6`, success `#66BB6A`; `onX` = `#000000`-ish contrast text: use `Color(0xDE000000)` (black at 87 %) for all three, as MUI's `getContrastText` does for these light hues.
  - light: warning `#ED6C02`, info `#0288D1`, success `#2E7D32`; `onX` = `#FFFFFF`.
  - containers: the intent at 16 % (dark) / 8 % (light) alpha-blended over the card surface (`scheme.surfaceContainerLowest`), like the existing `errorTint`; `onXContainer` = the intent colour itself in dark, and the intent darkened 30 % in light (`Color.lerp(intent, const Color(0xFF000000), 0.3)`). Note: `successContainer`/`onSuccessContainer` (the existing pair) stay the existing fixed greens for backward compatibility; the new `success`/`onSuccess` are the intent + on-colour. Say in the doc comment that `successContainer` is the capsule green and `success` the semantic intent.
- `copyWith` and `lerp` cover all ten new fields.
- `ForgeStatusCapsule`: add `ForgeStatusTone { neutral, success, warning, info }` and a `tone` parameter; keep `active` (deprecated-style note in the doc comment is enough, no `@Deprecated` annotation) meaning `tone: success`. Fill/text: success → `successContainer`/`onSuccessContainer` (unchanged look), warning → `warningContainer`/`onWarningContainer`, info → `infoContainer`/`onInfoContainer`, neutral as today.
- Export: `lib/forge_ui.dart` exports everything under `src/` already; verify the enum is reachable.
