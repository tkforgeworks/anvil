# T-059 report — domain editors (area `dom`)

Baseline `a0823e2` on `review/1.0.0-baseline`. 50 files, 11,781 lines under `lib/app/domains/`.
`fvm flutter analyze lib/app/domains`: "No issues found!". The tree was still clean afterwards (`?? node_modules/` only).

## 1. Summary

The six domains work and pass analysis. They grew one ticket at a time, though, so the same editor is written out six times in two dialects. Abilities, classes and recipes use a `tabLabels` list, a `_TabLabel` widget and a Text load error. Items, loot tables and NPCs use a tab enum, an `onBack` parameter and a `ForgeErrorCard`. The domain-specific parts are concentrated in five oversized files.

The top three problems:
1. **Five files mix several widgets each.** `classes_stat_growth_tab.dart` has 1,202 lines and 16 types. `npcs_editor_sections.dart` has 1,003 lines and 15 types. Also over the line: `loot_tables_editor_page.dart` (867), `recipes_editor_page.dart` (745) and `classes_derived_stats_tab.dart` (619).
2. **The editor scaffold is copied into every page**: back, duplicate, the tab row with its dirty dots, the bounded and unbounded layout, the export key field, the overview, the load error and the assignment rows. That copy is most of the 151- to 173-line `build()` methods. It is cross-area (T-058), but it blocks every per-domain split.
3. **Pure maths lives in the app.** `classes_growth_math.dart` and `classes_growth_fill.dart` import only `anvil_core`. Two loot-chance rules sit in widget files. Lookup providers are duplicated across domains: stats ×3, items ×3, max level ×2, abilities ×2, rarities ×2, custom-field definitions ×2.

## 6. Discrepancies

1. **CLAUDE.md (Domains) says every editor has "Duplicate disabled while dirty".** The item and recipe editors have no Duplicate button: no `duplicate` in `items_editor_page.dart` or `recipes_editor_page.dart`, and no `duplicate()` in their controllers. Duplicate exists only in their lists (`items_list_page.dart:117`, `recipes_list_page.dart:104`).
2. **CLAUDE.md says "`<domain>_pages.dart` registering both pages into `placeholders.dart`".** The pages files only define two builder functions (e.g. `items_pages.dart`). `placeholders.dart:12-17,47-70` imports them and does the registering.
3. **CLAUDE.md's editor-framework convention says "New domain UI uses these and adds nothing private".** All six domains define private copies of shared pieces (dom-F11 to F14). The rule is not followed today.
4. **CLAUDE.md known gap: "adapters read their repository through the page's WidgetRef".** True for 4 of 6. Abilities and classes hold a `ref.read` tear-off instead (`abilities_list_adapter.dart:23-25`, `classes_list_adapter.dart:23-25`). It is still the page's ref, so the gap applies to all six.
5. **CLAUDE.md "file names vary a little".** The variance is wider than its two examples: also `create_ability_dialog.dart`, `item_create_dialog.dart`, a split `classes_providers.dart` + `classes_growth_providers.dart`, singular vs plural provider names (dom-F25), and 13 `package:anvil/` self-imports.
6. **Metrics.** `files.csv` counts `classes_growth_fill.dart` as "files >1 public type", but it is a sealed hierarchy. The brief rounds the class controller to 350 lines; `files.csv` says 351. The domain file counts match (7/14/7/7/8/7 = 50).
