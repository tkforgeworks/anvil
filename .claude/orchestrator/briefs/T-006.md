## Expected outcome
`packages/anvil_core` exposes, through `package:anvil_core/anvil_core.dart`:

- `final class ProjectDatabase` owning the `sqlite3` `Database` privately. Surface:
  - `factory ProjectDatabase.open(String path)`: read-write, creates the file if absent, runs
    `PRAGMA journal_mode = WAL` and `PRAGMA foreign_keys = ON`. Does NOT run migrations (the
    runner is called explicitly; the lifecycle ticket decides when).
  - `factory ProjectDatabase.openReadOnly(String path)`: `OpenMode.readOnly`, `foreign_keys = ON`
    (WAL is persisted in the file, so do not try to set it on a read-only handle if that errors;
    find out and document in a comment).
  - `String get path`, `bool get isOpen`, `void close()` (idempotent).
  - `void integrityCheck()`: runs `PRAGMA integrity_check`; a single row `ok` passes; anything
    else, or a `SqliteException`, throws `IntegrityCheckFailed(message)`.
  - `void snapshot(String path)`: `VACUUM INTO ?` to a new file (the only sanctioned way to copy
    a project; §5.5).
  - `void checkpoint(CheckpointMode mode)` with `enum CheckpointMode { passive, full, restart,
    truncate }` mapping to `PRAGMA wal_checkpoint(MODE)`.
  - `T read<T>(T Function(ReadScope tx) body)`: `BEGIN` (deferred) … `COMMIT`, `ROLLBACK` on
    throw when `!autocommit`; `ReadScope` exposes `ResultSet select(String sql, [List<Object?>
    parameters = const []])` only. Synchronous (the design's `Future`s live on the repository
    interfaces, not here).
  - `@internal Database get handle` (package:meta) so `Sqlite*Repository` classes inside
    `anvil_core` can use the raw handle later without the app seeing it. Document that in a
    doc comment.
  - `open`, `openReadOnly`, `snapshot`, `checkpoint` and `read` may propagate `SqliteException`
    for now; the project-lifecycle ticket (C12 / ANVL-182) wraps those at its layer. Say so in a
    doc comment on the class. The runner and `integrityCheck` must never let one out.
- `errors.dart`: `final class MigrationFailed implements Exception` with `filename` and `cause`,
  and `final class IntegrityCheckFailed implements Exception` with `message`; both with useful
  `toString()`.
- Migrations: `migration.dart` defines `final class Migration { final String filename; final void
  Function(Database db) up; }` (or a record; your call, keep it tiny). Each `m00N_*.dart` holds one
  `Migration` constant whose `filename` is exactly the Electron filename without `.ts`
  (`001_init`, `002_seed_meta_layer`, `003_class_overrides_and_metadata`,
  `004_ability_resource_type`, `005_custom_templates`, `006_stat_growth_formulas`,
  `007_save_history`) and whose SQL is the Electron SQL verbatim: same statements, same order,
  the `IF NOT EXISTS` clauses, 001's `copyLegacyProjectMeta` (with its `tableExists` check) and
  002's re-run of 001's `up`. `migrations.dart` exports `const allMigrations = [...]` in order and
  `const currentSchemaVersion = 7` (assert in a test it equals `allMigrations.length`).
- `migration_runner.dart`: `List<String> pendingMigrations(ProjectDatabase db)` and
  `void runMigrations(ProjectDatabase db)` reproducing `runner.ts`: create `schema_migrations
  (filename TEXT PRIMARY KEY, applied_at TEXT NOT NULL)` if absent (same SQL text); read the
  applied set; for each pending migration run `up` and the `INSERT INTO schema_migrations` in
  ONE transaction (`BEGIN` … `COMMIT`, `ROLLBACK` on failure), `applied_at` in the JS ISO format;
  on failure throw `MigrationFailed(filename, cause)` and stop; if any migration ran, execute
  `UPDATE project_info SET schema_version = ?, updated_at = datetime('now') WHERE id = 1` with
  `currentSchemaVersion`. No logging (the core has no logger yet).
- Tests (`dart test` style, `package:test`), each opening a fresh temporary copy of the fixture
  through `FixtureCopy` and asserting in `tearDown` that `test/fixtures/sample-0.1.6.anvil`'s
  bytes are unchanged:
