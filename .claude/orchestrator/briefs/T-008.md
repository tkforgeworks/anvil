## Expected outcome
Through `package:anvil_core/anvil_core.dart`:
- `ProjectService({required String supportDirectory})` (constructor injection; the app passes
  the application-support directory; `recent-projects.json` lives directly in it as in Electron).
- `Future<CreateResult> create({required String projectName, required String gameTitle,
  required String parentFolder})`: `createProjectFolder` builds
  `{ParentFolder}/{sanitized name}/database/`, `exports/`, `temp/`, `logs/` and fails if the
  project folder exists; file path `{folder}/database/{sanitized name}.anvil`; acquire lock, open,
  `runMigrations`, `integrityCheck`, upsert `project_info` (name, game title,
  `schema_version = currentSchemaVersion`) exactly as `createProject` does, add to recents,
  return a `ProjectSession`. On any failure: close, release the lock, delete the whole folder
  tree, rethrow as `ProjectCreateFailed(message, cause)`.
- `Future<OpenResult> open(String path)` where `OpenResult` is a sealed class:
  `ProjectOpened(session)`, `ProjectNeedsUpgrade(path, schemaVersion)` (lock is held while the
  caller decides; provide `Future<ProjectSession> upgradeCopy(String path)` and
  `void cancelUpgrade(String path)` that releases the lock), `ProjectRecovery(fileName, message)`
  (integrity failure or any non-lock open error; nothing stays open, lock released). A lock
  conflict throws `ProjectLocked` with the message exactly
  `This project is already open in another Anvil window.` (not a recovery case). Missing file:
  `ProjectRecovery` with Electron's message if it has one, else a clear message (report which).
- Upgrade copy: snapshot of the original to `{name}_backup_{timestamp}.anvil` beside it using
  0.1.6's exact timestamp format (read `createBackupPath`: ISO string with non-digits stripped,
  verify), migrate the copy, `integrityCheck`, `checkpoint(truncate)`, acquire the copy's lock
  BEFORE releasing the original's, then open the copy as the session. The original's bytes are
  unchanged afterwards (test it with sha256 on a fixture copy; the fixture is schema 7, so to get
  a below-7 file set `project_info.schema_version` lower and delete rows from
  `schema_migrations` on a copy, which is what Electron would see for an old file).
- `Future<void> close(ProjectSession)`: `checkpoint(truncate)`, close the handle, release the
  lock. The dirty-editor guard is UI (not here).
- `Future<ProjectSession> saveAs(ProjectSession, String targetPath)`: append `.anvil` if missing,
  same path is a no-op returning the same session, target must not exist (`ProjectSaveAsFailed`
  otherwise), `snapshot(target)`, move the lock, reopen the copy; on failure reopen the original
  and rethrow.
- `Future<void> backup(ProjectSession, String targetPath)`: `snapshot(target)`; active project
  unchanged. Also `String defaultBackupPath(ProjectSession)` =
  `{project dir}/{name}-backup-{YYYY-MM-DD}.anvil` (verify against `backupProject`).
- Lock: `<file>.anvil.lock`, `File.create(exclusive: true)` semantics, JSON
  `{"pid": <int>, "lockedAt": "<ISO 8601>", "filePath": "<path>"}` in that key order with the same
  JSON formatting Electron writes (check whether it is `JSON.stringify` compact or indented and
  match it); case-insensitive path comparison for "is this ours"; deleted on close. No stale-lock
  detection.
- Recent projects: `List<RecentProject> recentProjects()` refreshed from disk (exists, file size,
  modified time, folder structure via `detectProjectFolder`), max 10 newest first, de-duplicated
  case-insensitively by path, `removeRecent(path)`, `clearRecents()`; JSON shape identical to
  0.1.6 (same keys and nesting as `RecentProject`; write a test that loads a hand-written
  0.1.6-shaped file and round-trips it). A corrupt or missing file reads as empty.
- `ProjectMetadata` carries `projectName, gameTitle, filePath, projectFolder (nullable),
  schemaVersion, lastModifiedAt (ISO), fileSize, recordCounts`.
- Tests (`package:test`, fixture copies via `FixtureCopy`, fixture bytes unchanged in `tearDown`):
  create (folder tree, file, lock, `project_info`, recents; failure path removes the tree); open
  the fixture copy (returns `ProjectOpened`, metadata matches the fixture's `project_info` and
  counts); lock conflict with a lock file written by hand in 0.1.6's exact JSON throws
  `ProjectLocked` with the exact message; a downgraded copy returns `ProjectNeedsUpgrade`,
  `upgradeCopy` writes the backup with the expected name pattern, the copy is at schema 7 and
  locked, the original is byte-identical and unlocked; corrupted copy (overwrite row bytes
  inside a populated page, e.g. the `stats` page; free space reports `ok`) returns
  `ProjectRecovery` and leaves no lock; `close` removes the lock and leaves no `-wal` content;
  `saveAs` and `backup` produce openable files with zero pending migrations; recents max 10,
  de-dup, refresh, remove, clear. `SqliteException` must not escape any public method (wrap).
