## Goal
One guard, at the route and the project level, that asks Save / Discard / Cancel whenever a dirty
editor draft would be left: Back from a full-page editor, closing an editor dialog (X, Esc,
backdrop), navigating to another record or page, closing or switching the project (menu rows,
Ctrl+W, Ctrl+O, Ctrl+N, Save As). Window close and quit are already guarded by ANVL-187's
`AppExitHandler`. Design §8.8 (the bullets at lines ~415-416 of
`design_notes/Anvil_Implementation_Design_v2_0.md`). Jira ANVL-161 (the orchestrator handles Jira).

## Decisions already taken (do not reopen)
- `lib/app/editor/exit_prompt.dart` gains `confirmLeaveEditor(context, ref, DirtyEditor entry)`:
  true at once when the entry is clean; otherwise a `LeaveEditorDialog` titled `Unsaved changes`
  for one editor with **Save** (disabled while the entry has blockers; on a failed save the dialog
  stays open with the error shown and returns nothing yet), **Discard** (discards, returns true),
  **Cancel** (false; also Esc and barrier). Reuse `LeaveAllDialog`'s styling and strings where they
  fit. `confirmLeaveAll` stays as is for the project-level and exit paths.
- A `leaveGuardProvider` (`Provider<Future<bool> Function()>`) in `lib/app/editor/exit_prompt.dart`
  whose default calls `confirmLeaveAll` through `rootNavigatorKeyProvider.currentContext` (true when
  there is no context). `ProjectLifecycleNotifier.openPath`, `create`, `closeProject` and `saveAs`
  call it before setting busy and before `_closeCurrent`, and return (doing nothing) when it answers
  false. `openWithDialog` keeps asking for the file first, then goes through `openPath`, so the guard
  runs once. Tests override the provider.
- Route level, full page: each `<location>/:id` editor route in `app_router.dart` gets `onExit` that
  finds the dirty entry for that domain and record id in `dirtyEditorsProvider` and, if any, runs
  `confirmLeaveEditor`. Navigating to another record of the same domain is a route change too
  (verify go_router calls `onExit` for a same-route parameter change; if it does not, make the
  editor pages keyed by record id and guard the change in `openEditor` before `context.go`).
- Route level, modal: `EditorDialog` wraps its content in a `PopScope` that is `canPop` only while the
  editor is clean (`EditorDialog` gets a `domain` and `id` so it can look the entry up through a
  `Consumer`), `onPopInvokedWithResult` runs `confirmLeaveEditor` and pops on true; the X button calls
  `Navigator.of(context).maybePop()`. A second editor opened from inside a dialog (inspector rail
  link) stacks a second dialog, so no guard is needed there.
- `openEditor` for a full-page target does not prompt itself; `onExit` does. Clean drafts never prompt.
- Keep `RecordEditorScope` watch-free. The lookups go through `dirtyEditorsProvider`, which already
  holds everything the guard needs.
