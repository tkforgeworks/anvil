# T-053: Fresh project metadata after writes and on close (ANVL-204)

You are a subagent dispatched by an orchestrator. Do exactly this task, then report in the format
at the end. If blocked, stop and report.

## Goal
`ProjectSession.metadata` stops being frozen at open. While a project is open the dashboard shows
current metadata after every write, and closing a project rewrites its recent-projects entry from
the database, so the Welcome page shows the new game title and record counts straight after close.

## Why (read before coding)
The ticket says the dashboard hero shows a stale game title. Checked by the orchestrator: no screen
shows the game title while a project is open (the hero shows `projectName`, which is not editable;
0.1.6's dashboard did not show the title either). The title is shown only in the Welcome page's
recent list (`lib/app/welcome/recent_projects_list.dart`). 0.1.6 rewrote the recent entry on every
project Save (`updateRecentProjects` in `src/main/project/project-service.ts` `saveProject`), which
0.2.0 does not have, so in 0.2.0 the entry keeps the title and record counts from the last open
until the next open. The dashboard hero's file size and its `lastModifiedAt` fallback are frozen at
open for the same reason (`lib/app/dashboard/dashboard_providers.dart` `dashboardProjectProvider`
doc comment says so).

## Decisions already taken
- Core: `ProjectSession.metadata` becomes a getter over a private field. Add
  `ProjectMetadata ProjectService.refreshMetadata(ProjectSession session)`, which rebuilds the
  metadata with `_buildMetadata(session.database, session.filePath)`, stores it on the session
  (through an `@internal` setter or method on `ProjectSession`) and returns it. It throws
  `StateError` if the session is closed. No `SqliteException` escapes it.
- Core: `close(session)` refreshes the metadata and writes it to the recent list (`_addRecent`)
  before the checkpoint, while the database is still open. A refresh failure never fails the close
  (catch, keep the old entry; leave a `TODO(ANVL-173)` log comment like the others).
- App: `dashboardProjectProvider` watches `writeEpochProvider` and returns
  `ref.read(projectServiceProvider).refreshMetadata(session)` (null with no session), so the hero's
  file size and fallback timestamp follow writes. Update its doc comment. Nothing else in the app
  needs to change unless a test shows it.
- Do not add the game title to the dashboard; the ticket's third criterion is replaced by the
  Welcome-page test below (the orchestrator will amend the ticket).
