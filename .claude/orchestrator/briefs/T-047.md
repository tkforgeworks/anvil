## Ticket acceptance criteria (ANVL-156)
- A template registry keyed by template id, each defining the meta layer it seeds: stats,
  rarities (with colours), item categories, NPC types, crafting stations, crafting
  specializations, derived stat definitions (formula, output type, rounding mode) and project
  defaults such as max level.
- Project creation applies the selected template after migrations run, inside the same failure
  path, so a template error triggers the existing cleanup (folder removal, lock release).
- `blank` yields exactly what migration 002 seeds today.
- `fantasy-rpg` and `sci-fi-rpg` each produce a visibly different, coherent meta layer: distinct
  stat sets, rarity tiers, categories, stations, and at least one derived stat each. Content is
  proposed in the PR.
- Seeded rows use the three-part identity (internal id, display name, export key) and are applied
  exactly once, at creation.
- A test per template asserts the seeded rows.
- A newly created project is not marked dirty and has no spurious save-history entries.
- The template selector is shown again in the New Project dialog, and the README describes
  templates as shipped.

## Decisions already taken (do not reopen)
- Core: `packages/anvil_core/lib/src/project/templates/` holds `enum ProjectTemplate { blank,
  fantasyRpg, sciFiRpg }` carrying the 0.1.6 id strings, display names and a one-line description,
  and a `ProjectTemplateContent` value per template (the lists above plus `maxLevel`). Exported
  through `lib/anvil_core.dart`. Blank's content is empty: Blank changes nothing after migrations.
- Fantasy and Sci-Fi REPLACE the migration-002 meta rows (delete those rows from the meta tables,
  insert the template's) rather than adding to them. Migration 002 itself is untouched.
  `project_info.max_level` is set from the template.
- Seeding runs in `ProjectService.create` after `runMigrations` and before `integrityCheck`,
  inside the existing `try`, as ONE plain SQL transaction on the handle (not `saveTransaction`,
  which would write a `save_history` row). Ids follow m002's id style; export keys match
  `^[a-z0-9_-]+$`; every derived-stat formula must pass `validateFormula` against that template's
  own stats (a test asserts it) and `validateProject` on a fresh project of each template returns
  no errors.
- `ProjectService.create` gains `ProjectTemplate template = ProjectTemplate.blank`;
  `ProjectLifecycleNotifier.create` passes it through. A test injects a failing template path (e.g.
  a test-only content whose insert violates a constraint, through whatever seam you add with
  `@visibleForTesting`) and asserts the folder is removed and no lock remains.
- App: `CreateProjectDialog` shows a `Template` picker (Blank preselected) with the description as
  helper text. Restore the Welcome tile wording from 0.1.5 if it mentioned templates, else leave it.
- Content: propose it yourself. Coherent, modest sizes (5-8 stats, 4-6 rarities with distinct hex
  colours, 5-8 categories, 3-5 NPC types, 3-5 stations, 2-4 specializations, 2-3 derived stats).
  List it in your report so it can go into the PR description.
