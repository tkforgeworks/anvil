## Decisions already taken (do not reopen)

  - `list_domain_adapter.dart`: `abstract interface class ListDomainAdapter<R>` the domain pages
    implement over their repository: `ShellDomain get domain`, `Future<List<R>> list(RecordListMode)`,
    `String idOf(R)`, `String displayNameOf(R)`, `String exportKeyOf(R)`, `List<ListColumn<R>> get columns`
    (label, cell builder, optional comparator), `Future<void> softDelete/restore/hardDelete(id)`,
    `Future<R?> duplicate(id)` (returns the new row so the page can open it), and
    `Future<String?> searchText(R)` is NOT a thing — search is over display name and export key plus
    `extraSearchText(R)` (a `String` the adapter supplies, default empty).
  - `record_list_controller.dart`: `RecordListController<R>` (an `AsyncNotifier` family keyed by the
    adapter or domain; your call, document it) holding `mode` (active/archived), `query`, sort
    column and direction, selection (`Set<String>`), and the loaded rows; `build()` watches
    `writeEpochProvider` so every write anywhere refreshes the list; actions `softDelete`, `restore`,
    `hardDelete`, `duplicate`, `bulkSoftDelete`, `bulkRestore`, `bulkHardDelete` go through the
    adapter or `lifecycleRepositoryProvider` and bump the epoch once each after the write returns.
    Errors (`SaveFailed`, `RecordNotFound`) surface as a `lastError` string the page shows; nothing
    throws to widgets.
  - `list_toolbar.dart` (`ListToolbar`: search field, `filterSlot`, sort menu — `DropdownButton` or a
