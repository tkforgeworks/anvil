## 4. Installer tool and Electron-upgrade expectation
- **Tool: Inno Setup 6**, following lazy-sleeper-app (LS-73). `release-flutter.yml` already assumes it ("Inno Setup 6 ... on the windows-latest image"), and it covers all of the required behaviour. LS published v0.1.0-rc.1 with a setup.exe through this pipeline.
- **What 0.1.6 installed** (read from app-builder-lib 26.15.7 in the main checkout's `node_modules`, read only):
  - Install dir: `%LOCALAPPDATA%\Programs\Anvil` per user, `Program Files\Anvil` for all users.
  - Uninstall key: `...\Uninstall\268ba5f3-2477-54c8-a960-331b2ce83d97` (UUID v5 of `com.tkforgeworks.anvil` in electron-builder's namespace; Node and Python agree on the value). It lives in HKCU or HKLM (64-bit view) and holds `UninstallString "<dir>\Uninstall Anvil.exe" /currentuser|/allusers`.
  - `Software\<guid>\InstallLocation`.
  - Shortcuts `Programs\Anvil.lnk` and `Desktop\Anvil.lnk`.
- **Why removal is needed.** Inno's key is always `<AppId>_is1`, so it can never take over that entry, and the default folders are the same. A plain install would therefore mix Electron and Flutter files in one folder (Electron `Anvil.exe` = Flutter `anvil.exe` on NTFS) under two "Anvil" Apps entries. Uninstalling 0.1.6 later would then `RMDir /r` the shared folder.
- **What the installer does.** `PrepareToInstall` reads that key and runs a `{tmp}` copy of the 0.1.x uninstaller with `/S /KEEP_APP_DATA /currentuser _?=<dir>`, waiting for it. This is how electron-builder's own installer removes an old version. A non-zero result aborts setup with a message to uninstall from Settings > Apps.
  - The HKCU install is always handled.
  - The HKLM (all-users) install is removed only in an all-users (admin) install.
- **Expected results (for Tim's Windows 11 test):**
  - Per-user 0.1.6, then per-user 0.2.0: **replaces**. One "Anvil" entry remains, in the same folder.
  - All-users 0.1.6, then all-users 0.2.0: replaces.
  - All-users 0.1.6, then per-user 0.2.0: **side by side** in different folders, with two "Anvil" Start Menu entries (per-user and common).
  - In every case, `%APPDATA%\Anvil` (0.1.6 settings and recents) and `.anvil` files are kept.
  - 0.2.0 keeps its own data under `%APPDATA%\TK ForgeWorks\Anvil` (path_provider: CompanyName\ProductName), so 0.1.6 recents and settings do not carry over (§10).

**Replace "Release process (RC → stable)" with:**

1. Topic branches named `vX.Y.Z/ANVL-N-short-topic` are cut from and PR'd **into** the release branch (e.g. `v0.2.0/main`), never into main. Delete the topic branch after merge.
2. **Cut an RC**: `scripts/release/bump-version.sh rc` (or `.ps1 rc` on Windows) on the release branch. The base version comes from the branch name, so there is no patch/minor/major to choose.
