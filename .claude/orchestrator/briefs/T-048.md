## Decisions already taken (do not reopen)
- Tim, 2026-11-03: the Custom Fields tab KEEPS saving immediately (design §13.5). It is not part of
  the Project Settings draft or its Discard. Only its field-definition delete gains a confirmation.
- Both dialogs register a `DirtyEditor` entry in `dirtyEditorsProvider` while dirty (removed when
  clean, saved, discarded or disposed), so the existing app-exit / project-close / project-open
  prompt lists them. To allow that, `DirtyEditor` gains an optional `kindLabel` (String) used by
  the prompts instead of `domain.singular` when set, and `domain` becomes nullable ONLY if needed
  for this (prefer keeping `domain` required and adding a separate constructor `DirtyEditor.other`
  with `kindLabel` and no domain — your call, but every existing caller must compile unchanged and
  `saveStatusProvider` must count these entries as unsaved). Labels: `Project Settings` with
  `kindLabel: 'settings'`, and `<template name> (template)` (`kindLabel: 'template'`, a new template
  shown as `New template`).
- Dismissing either dialog while dirty (Cancel, close button, Esc, barrier) runs
  `confirmLeaveEditor` with that entry: Save (disabled while blocked) commits and closes, Discard
  closes with nothing written, Cancel stays. Clean dialogs close at once as today. Saving with no
  changes writes no history row (already true for settings; make it true for the template dialog:
  Save is disabled while clean, as record editors do).
- The template dialog's draft is a value-equal record of the four fields against a baseline (the
  stored template, or empty for New); no undo stack in either dialog.
- Deleting a custom field definition shows a confirm dialog `Delete field "<name>"?` with
  `This cannot be undone.` and Cancel / Delete (danger style as the existing
  `showPermanentDeleteDialog`); a refusal (`SaveBlocked`) still shows the repository message inline
  as today, which is the impact display. Template delete already confirms (ANVL-200); leave it.
- Do NOT edit `lib/app/export/export_controller.dart` or `export_page.dart` (ANVL-117 runs in
  parallel and edits the controller). If the template dialog truly needs a controller change, stop
  and report.
