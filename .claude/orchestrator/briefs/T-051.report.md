# T-051 report: About Anvil dialog (ANVL-203)

## 1 Outcome
Done. Help > About Anvil opens Flutter's `showAboutDialog` with the name `Anvil`, the running version (no `+build`), `© <year> TK ForgeWorks · Apache-2.0` (the year comes from `clockProvider`), 0.1.6's `RPG Data Management Tool` line, `Repository` and `Report an issue` link buttons through `openExternal`, and the framework's View licenses / Close buttons. The command is enabled whether or not a project is open, and the `Not yet in 0.2.0` tooltip is gone.

## 2 Changes
- `pubspec.yaml`: `package_info_plus: ^10.2.2`, with a comment that only `about_dialog.dart` imports it. 10.2.2 is the latest release: `pub add` resolved it and `pub outdated` lists no newer one. `pubspec.lock` is kept. Its new entries: `package_info_plus` 10.2.2, `package_info_plus_platform_interface` 4.1.0, and transitive `win32` 6.4.0 and `ffi_leak_tracker` 0.1.2.
- `lib/app/menu/about_dialog.dart` (new):
  - `repositoryUrl` and `issuesUrl`.
  - `appVersionProvider`: a `FutureProvider<String>` over `PackageInfo.fromPlatform().version`, passed through `stripBuildNumber`.
  - `aboutLegalese(year)`.
  - `showAnvilAboutDialog(context, ref)`: reads the launcher, the year and the version before the dialog opens, so the dialog does not depend on the menu's `ref` staying alive. If the version can't be read, the dialog shows none.
- `lib/app/menu/menu_commands.dart`:
  - `about` is no longer in the disabled switch or the tooltip switch.
  - The new `case MenuCommand.about` opens the dialog on the root navigator context.
  - Adds the `about_dialog.dart` import.
- `test/menu/about_dialog_test.dart` (new, 5 tests):
  - The pure helpers.
  - The menu path with the version overridden to `0.2.0-rc.1`: the version, the legalese (year 2027 from the clock), the tagline and View licenses are all found, both links launch the right URLs, and Close works.
  - View licenses opens `LicensePage`.
  - A version read that throws shows no version.
  - With no session: `commandEnabled` is true, `disabledTooltip` is null, and dispatching the command opens the dialog.
- `linux/flutter/` and `windows/flutter/` generated plugin files: **unchanged**. `package_info_plus` is a Dart-only plugin (`dartPluginClass`) on both platforms.

- What the version shows:
  - **Linux:** the plugin reads `data/flutter_assets/version.json`. The debug bundle has `{"version":"0.2.0","build_number":"1",...}`, so it shows `0.2.0`; on an RC it would show `0.2.0-rc.N`.
  - **Windows:** the plugin reads the exe's `ProductVersion` string and splits it on `+`. `Runner.rc` sets that string to `FLUTTER_VERSION`, which `flutter_tools/lib/src/cmake.dart` writes as the full `0.2.0-rc.N+BUILD`, so it shows `0.2.0-rc.N`.
  - The Windows result comes from reading that source, not from running on Windows. I also did not launch the Linux GUI.

## 4 Deviations
- Added the `RPG Data Management Tool` line as a child of the dialog, matching 0.1.6's `AboutModal.tsx`. The alternative was the brief's links-only list.
- The repository and issue URLs live in `about_dialog.dart`, not `external_links.dart`, because `external_links.dart` is outside Scope.
- If the platform can't read the version, the dialog shows none, so it still opens. The alternative was letting the error propagate.
