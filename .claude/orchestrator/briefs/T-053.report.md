# T-053 report: fresh project metadata (ANVL-204)

## 1 Outcome
Done. `ProjectSession.metadata` is now a getter with an `@internal` setter. `ProjectService.refreshMetadata(session)` rebuilds the metadata, stores it on the session and returns it. `close` writes the refreshed metadata to the recent list before the checkpoint. `dashboardProjectProvider` re-reads the metadata on every write-epoch bump. After a close, the Welcome page shows the new game title and record counts. Nothing is committed.

## 2 Changes
- `packages/anvil_core/lib/src/project/project_session.dart`: private `_metadata`; `metadata` getter; `@internal set metadata`. The constructor signature is the same (`ProjectSession(metadata, database, lock)`).
- `packages/anvil_core/lib/src/project/project_service.dart`:
  - New `refreshMetadata(session)` (a new `// metadata` section). It throws `StateError('The project session is closed.')` when `!isOpen`. Any other failure is best effort: it keeps and returns the previous metadata, with a `TODO(ANVL-173)` log comment. So no `SqliteException` or `FileSystemException` escapes it.
  - `close` now runs `_addRecent(refreshMetadata(session))` first, inside `if (session.isOpen)`, then the checkpoint. Doc updated.
  - `_buildMetadata` now throws `FileSystemException` when `statSync` reports `notFound`. Before, it silently produced `fileSize: -1` and an epoch timestamp. That could not happen at open/create but could during a refresh.
- `lib/app/dashboard/dashboard_providers.dart`: `dashboardProjectProvider` watches `writeEpochProvider` and `projectSessionProvider`. It returns null with no session, and `session.metadata` for a closed session (no `StateError` in a widget). Otherwise it returns `ref.read(projectServiceProvider).refreshMetadata(session)`. Doc comment rewritten; it notes that the main file's size and mtime move only on a WAL checkpoint.
- `packages/anvil_core/test/project/project_service_test.dart`: new `refreshMetadata` group with 5 tests:
  - title after `saveProjectSettings`
  - item count +1 after `items.create`
  - closed session → `StateError`
  - file renamed away → previous metadata kept
  - `close` → a fresh `ProjectService(...).recentProjects()` entry has the new title and the `items: 6` counts
- `test/welcome/fresh_metadata_test.dart` (new): opens the real fixture through the Welcome page, saves a new title through `session.meta` and adds an item, then bumps `writeEpochProvider`. It asserts that `dashboardProjectProvider` has the new title and 6 items and is `same` as `session.metadata`. It then closes through File > Close Project (`ProjectLifecycleNotifier`). The Welcome row shows `Ashes of Forge`, no `Forge & Fable`, and `· 6 items · …`. I confirmed it fails (`Found 0 widgets with text "Ashes of Forge"`) when the close-time `_addRecent` line is removed.

## 4 Deviations
- Read failures in `refreshMetadata` keep the previous metadata; they do not throw. Rejected alternative: a new `ProjectMetadataFailed` subclass of the sealed `ProjectLifecycleFailure`. That class would have to live in `project_errors.dart`, which is outside Scope, and the dashboard would show an error over a transient read failure.
- Because of that, `close` needs no try/catch around the refresh: it cannot throw on an open session. The `TODO(ANVL-173)` comment sits in `refreshMetadata`.
- The missing-file guard in `_buildMetadata`, described in section 2, was added because the refresh made the `-1` size reachable.
- The app test asserts provider values, not the hero's on-screen file size. In WAL mode the main file's size does not change until a checkpoint, so a UI assertion on size would be timing-dependent.
