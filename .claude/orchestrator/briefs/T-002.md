## Goal
Implement Jira FU-10. `forgeTheme` currently sizes buttons with `minimumSize: Size.fromHeight(50)` (filled) and `Size.fromHeight(48)` (outlined): full-width, thumb-height. On desktop that stretches every button to its parent's width and, inside an unconstrained `Row`, throws "BoxConstraints forces an infinite width". Add a density parameter so desktop apps get content-sized buttons at desktop heights while phone apps are unchanged.

## Design (decided; implement this)
- New `enum ForgeDensity { touch, desktop }` in `lib/src/theme/forge_theme.dart` (or `forge_tokens.dart` if you prefer it next to `ForgeRadii`; export either way through `lib/forge_ui.dart`, which exports everything under `src/` already — verify). Doc comment: touch = the phone defaults the brand started on; desktop = mouse-driven apps (Anvil).
- `forgeTheme(..., ForgeDensity density = ForgeDensity.touch)`.
- In `ForgeDensity.desktop`:
  - Filled, outlined and text buttons: fixed height 36 (`minimumSize: Size(0, 36)`, `fixedSize` not needed; keep shapes/text styles), horizontal padding 16, `tapTargetSize: MaterialTapTargetSize.shrinkWrap`. No minimum width beyond content + padding. A `FilledButton` inside an unconstrained `Row` must lay out at intrinsic width with no error.
  - `inputDecorationTheme.contentPadding`: `EdgeInsets.symmetric(horizontal: 12, vertical: 10)`.
  - `searchBarTheme.constraints`: `BoxConstraints(minHeight: 40)`.
  - `listTileTheme`: `visualDensity: VisualDensity.compact` (or `dense: true`; pick one and test it).
  - `ThemeData.visualDensity: VisualDensity.compact`.
  - Segmented buttons and chips are already compact: leave them.
- In `ForgeDensity.touch`: every value exactly as today.
- Keep `forgeTheme` readable: a small private record/const per density (e.g. `_Metrics` with buttonHeight, buttonMinWidth, inputPadding, searchMinHeight, ...) chosen once at the top, rather than ternaries scattered through the builder.
