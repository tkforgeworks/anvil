## Decisions already taken (do not reopen)
- `DraftHistory<T>` goes in the core at `packages/anvil_core/lib/src/draft/draft_history.dart`,
  ported from the spike with its rules unchanged: `start(baseline)`, `edit(next, {coalesceKey,
  required now})` with the 500 ms same-key coalescing, the "burst returns to `past.last` drops the
  step" rule, the "edit landing on `past.last` is an undo" rule, `undo`, `redo`, `rebase({saved,
  persisted})`, `discard`, `isDirty = current != baseline`, `maxDepth = 200`,
  `coalesceWindow = 500 ms`. Keep it a `final class` with `const` constructor and unmodifiable
  stacks. Barrel `lib/src/draft/draft.dart` exporting it; `lib/anvil_core.dart` gains the one
  line `export 'src/draft/draft.dart';` in sorted position. Port the spike's 13 history tests to
  `packages/anvil_core/test/draft/draft_history_test.dart` (adapt imports; keep every case).
- App side in `lib/app/editor/` (new directory; file names are yours within it):
  - `EditorState<T>`: `history`, `saving`, `saveError` (String?, cleared by the next edit or
    save), `blockers` (`List<SaveBlocker>`, computed by the controller from the draft), getters
    `draft`, `baseline`, `isDirty`, `canUndo`, `canRedo`, `canSave = isDirty && blockers.isEmpty
    && !saving`. Hand-written `==`/`hashCode` are NOT required (history holds lists); do not add
    them.
  - `enum SaveOutcome { saved, nothingToSave, blocked, failed, busy }` as in the spike.
  - `abstract class RecordEditorController<T> extends AsyncNotifier<EditorState<T>>` taking
    `recordId` in its constructor (Riverpod 3 families pass the argument to the constructor).
    Abstract hooks the domain subclasses implement: `Future<T> loadDraft()`,
    `Future<T> saveDraft(T draft)` (returns the persisted draft read back in the transaction),
    `List<SaveBlocker> blockersFor(T draft)`, `String displayNameOf(T draft)`, and a
    `SaveDomain domain` getter (the enum from `save_descriptions.dart`) so the registry can
    group entries. Concrete members: `build()` (loads, starts the history, registers with the
    dirty registry via `ref.onDispose` for removal), `protected`-style `edit(T Function(T) change,
    {String? coalesceKey})` that applies the change through `history.edit` with `now` from
    `clockProvider`, recomputes blockers, clears `saveError`; `undo()`, `redo()`, `discard()`;
    `Future<SaveOutcome> save()` exactly as the spike's (busy / blocked / nothingToSave guards,
    snapshot, `saving: true`, `saveDraft`, `ref.mounted` check, `rebase`, on any exception keep
    the draft and set `saveError` to the exception's message for the §6.5 boundary types
    (`SaveBlocked` → its messages joined with a newline, `DuplicateExportKey` → its message,
    `SaveFailed`/`RecordNotFound` → their message) and `error.toString()` otherwise; return
    `failed`). `build()` watches nothing volatile; the repository reaches the subclass through
    its own constructor or `ref.read` in the hooks (ANVL-158 gotcha 6: say this in a doc
    comment).
  - `clockProvider`: `Provider<DateTime Function()>` defaulting to `DateTime.now`; tests
    override it to drive coalescing deterministically.
  - Dirty-editor registry: `dirtyEditorsProvider` (a `Notifier` holding an immutable list of
    `DirtyEditor(domain, recordId, displayName, Future<SaveOutcome> Function() save)` entries,
    ordered by registration). A controller adds/updates its entry whenever its state becomes
    dirty, removes it when clean, saved or disposed. Expose `isEmpty`, `entries`, and
    `Future<bool> saveAll()` that saves each in order and stops at the first non-`saved`
    outcome (returns false then). This is what ANVL-161's leave guard and ANVL-187's exit prompt
    consume; the prompts themselves are not built here.
  - `saveStatusProvider`: a sealed `SaveStatus` (`AllSaved`, `Unsaved(count)`, `Saving`,
    `SaveError(message)`) derived from the registry and the open controllers' `saving` /
    `saveError`. Keep it a plain `Provider` over the registry's state: give the registry entries
    a `saving` flag and `saveError` field that controllers keep current, so the status needs no
    knowledge of the family providers. The app-bar widget is ANVL-163; only the provider here.
- Repository providers (`classRepositoryProvider` etc.) are NOT part of this ticket: the
  `ProjectSession` fields they read arrive with ANVL-179 (in progress in parallel) and the
  providers land with ANVL-185. Say so in a doc comment on `RecordEditorController`.
- No widgets, no shortcuts layer (ANVL-162), no leave guard (ANVL-161), no `DraftTextField`
  (ANVL-187). This ticket is state only.
