Each column cell of a row that has actions is wrapped in `GestureDetector(translucent, onSecondaryTapUp)`, which calls `controller.open(position: globalToLocal(pointer))`. ## 4. Deviations
- **When `take()` runs.** The brief says "`build()` calls `take()` first". I call it right after the selector listing's `await`, before `_reloadRecords`. Riverpod 3.4.3 asserts "Providers are not allowed to modify other providers during their initialization" on any state change made during another provider's synchronous build (`element.dart` lines 800–813, `_notifyListeners`). A `take()` at the top of `build()` would trip that assertion. Rejected alternative: deferring the clear to a microtask, which would leave the request readable twice.
- **Cell hit area.** Inside the `GestureDetector`, the cell child sits in an `Align(centerStart)`. This lets a right-click anywhere in the cell's content area reach the row, not only on the text. Cell padding is still not covered. Rejected alternative: a bare wrapper, which only responds over the text's own width.
- **Actions column.** "Every data cell" is read as the column cells. The Actions cell (icon buttons) and the checkbox cell are not wrapped.
- **Focus on open.** The first menu row is focused in a post-frame callback after opening. Without that, a mouse-opened `MenuAnchor` has no focused row, and Arrow Down / Enter do nothing.
- **Domain mapping.** The export controller only maps `ExportDomain` → `ShellDomain` (private `_shellDomain`), so the reverse is the new extension in `list_domain_adapter.dart`, as the brief allowed.
- **Brief vs code.** All names in the brief matched the source: `RecordRowAction`, `actionsFor`, `actionKey`, `DataCell(..., onTap: open)`, `_actions` / `_open` / `_duplicate` / `_softDelete`, `_item` in `app_menu.dart`, `ExportScopeMode`, `setMode` / `setDomain` / `toggleRecord`, `exportDomainLabel`.
