## 4. Deviations
- `domain` became nullable. A `DirtyEditor.other` constructor cannot leave a non-nullable final field unset, so this was needed. The rejected alternative was a sentinel `SaveDomain`, which does not exist in the core and is out of scope.
- The prompt heading reads `There are unsaved changes:` when a non-record entry is listed, where it used to say "This record / These records". Leaving it would have called Project Settings a record.
- The template dialog's `TemplateDraft` compares the name and description trimmed, so trailing spaces alone do not make it dirty or write a history row. The source is compared as typed.
- Settings blockers are wrapped as `SaveBlocker('', message)`, because the controller holds them as strings.

## 6. Noticed, not done
- `export_page.dart` (out of scope) counts every registry entry in its note "Export reflects saved records only. N record(s) have unsaved changes". A dirty template dialog open over the page, or dirty settings, now counts there too. Its wording could filter to `domain != null`; that is ANVL-117's file.
- The app-bar `SaveStatusIndicator` tooltip says "N record(s) with unsaved changes", which now includes settings and template drafts.
- The template dialog keeps `_saveError` after later edits; record editors clear it on edit. This is the existing behaviour, left as it was.
- If the project closes while the settings dialog is open (app-exit Discard all, then close), `projectSettingsHeaderProvider` watches `requireSessionProvider`. This is the same known risk as an editor dialog left open over a closing project, and it was not exercised here.
