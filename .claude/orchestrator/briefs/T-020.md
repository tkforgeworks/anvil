## Decisions already taken (do not re-decide)
- `file_selector` (the Flutter team plugin) is added to the app `pubspec.yaml` (latest 1.x) for
  the folder picker and the `.anvil` open dialog. All dialog calls go through one app-side
  interface `FileDialogs` (`lib/app/dialogs/file_dialogs.dart`: `pickDirectory({initialDirectory})`,
  `pickAnvilFile({initialDirectory})`, returning null on cancel) with a `FileSelectorDialogs`
  implementation and `fileDialogsProvider` (root-level `Provider`, overridden in tests with a
  fake). Nothing else imports `file_selector`.
- Core change #1: `ProjectService` loses its `final` modifier (becomes `class ProjectService`) so
  app tests can `implements ProjectService` with a fake. That one-word change in
  `packages/anvil_core/lib/src/project/project_service.dart` is allowed; nothing else in the core
  changes except the recent-list passthroughs above if they are missing.
- The lifecycle state machine is a Riverpod notifier `ProjectLifecycleNotifier` in
  `lib/app/project/project_lifecycle.dart` with a sealed `ProjectLifecycleState`: `idle`,
  `busy(what)`, `needsUpgrade(path, schemaVersion)`, `recovery(fileName, message)`, `failed(message)`
  (lock conflicts and create failures surface here as a dismissible error). Intents:
  `openPath(path)`, `openWithDialog()`, `create(name, title, parentDirectory)`, `upgradeCopy()`,
  `cancelUpgrade()`, `removeRecent(path)`, `clearRecents()`, `dismiss()`. On success it calls
  `projectSessionProvider.notifier.set(session)` and logs through `appLoggerProvider`; it reads
  settings (`defaultSaveLocation`) at call time, never in `build()`.
- `WelcomePage` (`lib/app/welcome/welcome_page.dart`, with `recent_projects_list.dart`,
  `welcome_tiles.dart` or similar) is the home when `projectSessionProvider` is null;
  `lib/app/shell/project_open_placeholder.dart` (project name, game title, path, a Close Project
  button calling `ProjectService.close` then `clear`) is shown while a session is open, until
  ANVL-185 replaces it. `PlaceholderHomePage` is deleted; `ThemeModeSelector` moves unchanged to
  `lib/app/settings/theme_mode_selector.dart` (ANVL-189 uses it) and the debug-only gallery link
  moves to the welcome page footer.
- `CreateProjectDialog` (`lib/app/welcome/create_project_dialog.dart`) is opened by a top-level
  `Future<void> showCreateProjectDialog(BuildContext context)` so ANVL-186's menu can reach it
  from any app state; project name and game title required (trimmed), folder required, folder
  picker starts at `defaultSaveLocation` or the Documents directory (`path_provider`), the
  resulting path preview shows `{parent}/{sanitized name}/database/{sanitized name}.anvil` using
  the core's `sanitizeFolderName`.
- Failure presentations with the 0.1.6 wording: lock conflict shows `ProjectLocked.message`;
  upgrade asks `This project was created with an older Anvil schema.` / `Anvil will create an
  upgraded backup copy and leave the original project file unchanged.` with `Upgrade Copy` and
  `Cancel`; recovery mode replaces the welcome content with the file name and message and a way
  back (verify the exact strings and the button labels in `App.tsx` / `WelcomePage.tsx` and
  match them).
- Pure formatting helpers `formatFileSize(int bytes)` and `formatRelativeTimestamp(DateTime,
  {DateTime now})` in `lib/app/widgets/formatting.dart` reproduce the Electron components' rules
  and have unit tests.
