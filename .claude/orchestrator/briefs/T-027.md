## Decisions already taken (do not reopen)
- New directory `lib/app/menu/`:
  - `shortcut_registry.dart`: `ShortcutEntry(id, label, group, defaultBinding)` for all 24 0.1.6
    entries with the same ids and default bindings; `parseBinding(String)` → `SingleActivator`
    (the 0.1.6 string format from `shortcuts.ts`/`useGlobalShortcuts.ts`, e.g. `Ctrl+Shift+Z`;
    report the exact grammar you found); `effectiveBindings(registry, customShortcuts)` applies
    overrides and ignores unparsable ones with a warning through `appLoggerProvider`;
    `shortcutBindingsProvider` watches `appSettingsProvider` so overrides apply when settings change.
  - `menu_commands.dart`: one `MenuCommand` enum or sealed type per 0.1.6 command id, and
    `dispatchCommand(context, ref, command)` doing what `useCommandDispatch.ts` did, mapped to 0.2.0:
    New Project → `showCreateProjectDialog`; Open → `openWithDialog`; recents → `openPath`; Clear
    Recents; Save As / Backup → `fileDialogs` save location then `ProjectService.saveAs`/`backup`
    (add `saveAs(path)`/`backup(path)` to `ProjectLifecycleNotifier` if missing; that edit to
    `project_lifecycle.dart` is allowed, keep its shape); Close Project → `closeProject()` (the leave
    guard is ANVL-161); Quit → `SystemNavigator.pop()` or the exit request path the runners honour
    (check `lib/app/bootstrap/app_lifecycle.dart`; do not edit it); navigation entries → `context.go`
    on the shell routes; App Settings / Project Settings → open a small placeholder dialog saying
    "Coming in ANVL-189" / "ANVL-190" (so the rows exist and are testable); Validation / Export /
    Recycle Bin → their routes; Shortcuts cheatsheet → the dialog below; Zoom in/out/reset → the scale
    provider; external links → `openExternal(url)` which refuses anything but `https` and calls
    `url_launcher`; Save / Undo / Redo → `Actions.maybeInvoke` of `SaveRecordIntent`/`UndoDraftIntent`/
    `RedoDraftIntent` on `primaryFocus?.context`, disabled (row greyed, shortcut falls through) when
    no editor scope is in the focus chain (detect via `Actions.maybeFind<SaveRecordIntent>` on that
    context). Commands with no 0.2.0 target yet are disabled rows with a tooltip naming the ticket.
  - `ui_scale.dart`: `uiScaleProvider` (`Notifier<double>`, session-only, the zoom steps 0.1.6 used
    in `useCommandDispatch.ts`/`shortcuts.ts`; report the exact levels). It is applied in
    `lib/main.dart` through `MaterialApp.router(builder:)` with the standard whole-UI zoom pattern:
    a `LayoutBuilder` that lays the child out at `constraints / scale` inside `Transform.scale`.
    That `builder:` is the one edit to `main.dart` and also hosts `GlobalShortcuts` (below).
  - `shortcuts_dialog.dart`: the cheatsheet (Ctrl+/), 2-column grouped list of label + `KbdPill`
    (`kbd_pill.dart`) showing the effective binding, read from `shortcutBindingsProvider`.
  - `app_menu.dart`: `AppMenuButton` (the hamburger `IconButton` + `MenuAnchor` with five
    `SubmenuButton`s, `MenuItemButton` rows with `shortcut:` set from the effective bindings so
    the framework shows them, dividers, the recents `SubmenuButton` listing `recentProjectsProvider`
    with Clear Recents, repeatable entries (the 0.1.6 `KEEP_OPEN` set) with `closeOnActivate: false`).
  - `global_shortcuts.dart`: `GlobalShortcuts(child)`, a `Shortcuts` + `Actions` layer for the
    registry's intents, mounted in `main.dart`'s `builder:` around the router child so it is an
    ancestor of every editor's `RecordEditorShortcuts` (editor layers see keys first, §8.7). It never
    binds `UndoTextIntent`/`RedoTextIntent`. Its Save/Undo/Redo actions report `isEnabled` false
    when no editor scope is in the focus chain, so the key falls through; the other actions call
    `dispatchCommand`. Dialogs are separate routes and fall outside editor layers automatically.
